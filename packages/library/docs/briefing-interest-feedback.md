# Briefing interest terms and feedback

The `briefing/workbench` read returns ranked stories, the existing score explanation, and `matchedTerms` beside each row. `matchedTerms` is a read-time projection of that row's exact retained rank inputs: enabled, source-compatible interest terms that match its item title or excerpt and are not excluded, together with any terms already retained on the Story. It is sorted by interest ID and term. The exact `input.story` and its record reference remain unchanged; the projection is not written into historical Story bytes.

Consumers should render the returned terms for the mute action instead of maintaining a second matching rule. To mute one displayed term, submit the existing `briefing/feedback` operation with `{ requestId, targetKind: "term", targetId: "<displayed term>", action: "mute-term" }`. The same normalized term comparison used by ranking applies. The next workbench read suppresses stories matching that term. The response receipt contains the canonical feedback record and its exact ID.

Undo with `briefing/feedback/undo` and `{ requestId, feedbackId }`, using a fresh request ID and the prior feedback ID. Feedback and undo are append-only and idempotent under their request IDs. A subsequent workbench read reopens the story from the same owner store; no local optimistic visibility state is required. Unknown or nonmatching terms remain stored as explicit user feedback but do not hide unrelated stories.

The score remains a versioned explanation in the same row. Without active exact-story More/Less feedback it is `briefing-linear-v1`. With active feedback, `briefing-linear-v2` keeps term-based relevance unchanged and adds a separate signed manual-preference adjustment of 10 relevance-scale points per active choice, bounded to ±100 before weighting. The explanation includes the active feedback IDs. Undo removes only the chosen record and returns to the earlier result. This adjusts ordering, not topical matching, evidence strength or factual quality. `matchedTerms` still identifies only configured phrases actually found in the retained item text. Source policy, measured social observations, event timezone values and calendar export remain separate fields and owners.

Each ranked row also exposes `socialPulse`: observed counts and rates remain separate by item, platform, metric, scope, observation method and source reference. Counts represent distinct observation instants. Conflicting same-time readings or decreasing counters do not produce a growth rate; an absent pulse field from an older owner means unavailable, not zero.

For stories with explicitly item-linked events, `input.events` binds the score to those retained event records. Freshness uses time until the event starts and its matched interest half-life, rather than the feed capture age. Explicit active intervals score as ongoing; ended occurrences score zero. All-day events use calendar dates in their original timezone and an exclusive end date. Ambiguous times, invalid intervals or unsupported zones remain unknown. No recurrence is expanded or reminder scheduled by ranking. Stories without linked events use a plausible source-reported publication date for freshness when available and otherwise use host observation time; the source date remains unverified.
