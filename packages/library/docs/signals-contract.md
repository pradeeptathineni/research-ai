# Assessment and evidence contract

A finding has intrinsic evidence strength. A question has relevance. Contextual priority suggests a next action. Retrieval rank locates retained knowledge. None establishes personal novelty, usefulness or permission to execute a candidate.

## Interrupted research

Completed user-facing research notes can appear before the native turn finishes. They are bounded, provisional narrative, not admitted evidence, scored entities or a completed answer receipt. Reasoning and tool payloads do not become notes. Notes retain their order, so later progress or unfinished records do not erase earlier source pointers and qualifications. The partial-output limit is 24,000 UTF16 units or 64 notes; omitted notes are disclosed. Callbacks close when discovery ends, before final answer retention.

On timeout or cancellation, private mode retains the available narrative, provisional pointers, status and evidence gaps in the existing immutable run. Memory mode does not save it. If no usable narrative was produced, the result says so instead of inventing an answer. An interrupted verification can retain previously returned evidence with its actual state; it cannot declare unchecked sources verified or automatically save an eligible entity.

Reopen the retained run to discuss its frozen work explicitly. This is a separate bounded no-web follow-up, not resumption of the native process. It does not refresh changed sources, renew currentness, resolve missing or contradictory evidence, rewrite the original narrative or turn a partial note into a completed answer. Acquiring or assessing evidence further remains an explicit action.

## Durable research requests v1

The loopback API accepts `research-request-v1` on `POST search` alongside the existing unversioned request. All routes retain the existing Host, Origin and session-token guards. A missing token returns `403 {"code":"csrf_token_required"}` before body parsing, admission or dispatch.

On an explicitly selected fresh workspace, `POST request-scope` with `{}` initializes the private owner identity and epoch. It requires the session token, starts no research, and returns the existing scope when already initialized. `GET request-scope` only reads it. An interrupted initialization, missing ledger or corrupt ledger returns `503 request_store_unavailable`; initialization never repairs or replaces such a directory. Preserve this scope with each originating request. Do not initialize another scope to resolve uncertain work after storage loss or restore.

The closed v1 body requires `schema_version:"1.0"`, `request_id`, `idempotency_key`, `query`, `method:"answer-first"`, `profile:"quick"|"wide"`, `cache:"memory"|"none"`, `save:"never"`, `project_ref:null` and `authority_ref:{owner:"signals-ai",kind:"authority",id,revision,digest}`. Reference revision/digest may be null. IDs are bounded; keys use 1–128 ASCII letters, digits, `_ . : -`. Non-null projects, richer research bodies and other retention modes need a supported later envelope. An authority reference records the caller's context; it grants no permission beyond the authenticated local operation.

Send the previously bound epoch in `x-signals-owner-epoch`. Missing or changed epochs return `409 owner_epoch_mismatch`. The digest is `jcs-sha256-v1`: SHA256 over UTF8 JCS of `{action:"search",owner:{identity,epoch},request:semanticBody,execution_configuration:configurationRef}`. `semanticBody` is the normalized closed body with transport `request_id` and `idempotency_key` omitted; the key separately selects its durable admission. Normalization trims only the query's leading/trailing whitespace. JCS sorts object keys by UTF16 code units; malformed Unicode is refused. Authority reference/revision, profile and retention fields participate. Same key with changed semantic input returns `409 request_conflict` before dispatch. A request-ID-only retry returns the original job, digest and originally admitted `receipt.request_id`, preserving correlation without changing the request's meaning. The owner scope and response wrapper remain separate from the closed v1 receipt.

Before admission, the owner resolves a private execution snapshot: `{schema_version:"signals-execution-v1",runner,model,effort,acquisition,followedSources}` from validated settings/provider configuration. Model and effort must be explicit, nonempty owner selections; the durable route refuses blank selections before admission rather than deferring them to mutable native-host defaults. `configurationRef` is `{schema_version:"signals-execution-v1",digest_algorithm:"jcs-sha256-v1",digest}`, where `digest` hashes that snapshot using UTF8 JCS, including its booleans and arrays. Only digests are retained/returned; private paths, provider configuration and model selections are not copied into public metadata or the identity ledger. The captured settings and acquisition objects supply dispatch, followed-source scanning and the research kernel; none is reloaded after admission. This binds execution configuration, not the eventual research evidence, provider result or served-model identity.

`GET request-configuration` reads the current reference without initializing storage or probing a runner. Callers may persist it before send and pin its digest in `x-signals-execution-digest`. For a new key, changed configuration refuses with `409 request_configuration_changed` before admission. An existing-key retry compares semantic payload with the original and returns its original configuration reference even if current defaults changed; it never executes from those new defaults. An explicit expected digest that differs from the existing admission returns `409 request_configuration_conflict`. Use authoritative request lookup when current configuration itself is unavailable. Earlier ledger entries without a semantic/configuration binding remain readable, but submission requires explicit reconciliation (`409 request_identity_version_requires_reconciliation`); they are never silently rewritten or replayed.

Before entering research, Signals syncs an atomic admission (key, digest, job ID), then a dispatch-intent marker to `.signals/requests/ledger.json`. The private ledger has a versioned shape and checksum; writes sync the file and directory under an exclusive writer lock. A separate durable `head` is published first: missing or restored ledger snapshots then disagree with it and become unavailable. A crash between the head and snapshot also requires reconciliation. Restoring the entire store, including both files, cannot be detected locally; such restores must retire the old epoch and reconcile outstanding effects before admitting work. Question text, answer text, credentials and model output are absent from the ledger. Both cache options execute with memory retention. Explicitly saved records and historical receipt readers keep their existing behavior.

The `202` wrapper contains `id`, `receipt`, `deduplication` and `execution_configuration`. The receipt has `schema_version`, `request_id`, `idempotency_key`, `request_digest`, `digest_algorithm`, `state`, `run_ref`, `result_ref`, `reason` and `observed_at`. Its run reference identifies the API job; `result_ref` stays null because v1 does not retain an answer implicitly. Same-key retries return the original job and never enter research again. If another job holds the runner, the newly admitted request returns `409 runner_busy` with its admitted receipt; it remains known not dispatched and is never silently queued or retried.

`GET requests/{key}` and token-protected `POST requests/{key}/reconcile` with `{}` are query-only recovery routes using the same epoch header. They perform no writes or generation. `admitted/admitted_no_dispatch_intent` proves this owner has not crossed its dispatch boundary; `unknown/dispatch_may_have_started` preserves uncertainty, including a crash between the intent and spawn. Completion, partial, failure and cancellation settle separate terminal states. No startup scan or repeated POST replays an admitted or uncertain request. Existing `GET runs/{job}` and `POST cancel/{job}` remain available for the active process. After restart, a known durable job returns its receipt and `result:null` with explicit memory-result unavailability. Receipt lookup never regenerates an expired answer.

Terminal result expiry keeps the original identity/digest as an unknown tombstone. Unresolved work cannot expire. Entries are never automatically evicted; a full ledger refuses admission. Missing/corrupt state or a writer lock left by interruption requires owner inspection and reconciliation; locks are never displaced by age alone. A generic `404 not_found` with the current scope is an observation of absence, not proof of no effect. Identical-key retransmission is valid only under the same intact advertised dedupe scope and current authority. Lost/restored history or a changed epoch stays unresolved; never mint a replacement key to escape uncertainty. Explicit owner recovery and future retained-result contracts require separate qualification.

## Frozen follow-up requests v1

`POST followups` is a separate opt-in operation; `research-request-v1` keeps its closed answer-first meaning. The closed body requires `schema_version:"1.0"`, `request_id`, `idempotency_key`, `parent_ref:{owner:"signals-ai",kind:"answer"|"research_note",id,revision,digest}` with non-null `revision:"sha256:<digest>"`, `question` (1–2,000 units, trimmed), `scope:"saved-context-only"`, `retention:"private"` and the same `authority_ref` as v1. It shares the v1 ledger, epoch, execution-configuration pin and receipt shape. Its digest binds `action:"frozen-followup"`, so a key reused across operations conflicts.

The owner verifies the parent's exact retained bytes before admission and builds the existing bounded frozen material from them: the whole saved narrative as unverified prior synthesis, retained statements within the discussion budget with omissions counted, and the original gaps. One no-web discussion follows, with the existing prompt, schema and observation-ID binding. It searches, fetches, verifies and executes nothing. The child is retained as a private `answer` run whose ID is the durable job ID. It has an unassessed, Confidence-Unknown `answerReceipt` and a closed `followupOf` closure that copies the parent ref, question, frozen scope and its digest. A child about a stopped note stays explicit that the note remains incomplete. Parent bytes are never rewritten. Reopening validates the copy and never loads the parent or regenerates text, so a later missing parent leaves the child readable. A reply after cancellation or timeout is discarded. An interrupted retention write leaves the receipt `unknown`.

## Ask across saved research v2

`GET provider/capabilities` advertises the `frozen-followup-request` contract with versions `1.0` and `2.0`, and the mutating, authority-required `ask_across_saved_research` operation for `answer` and `research_note`. Consumers require both signals before offering the action. The provider transport remains version `1.0`; the request envelope selects the follow-up version. The existing v1 request, material, digest and closure behavior are unchanged.

`POST followups` accepts a closed v2 body with `schema_version:"2.0"`, `request_id`, `idempotency_key`, `parent_refs` (2–4 exact Signals `answer` or `research_note` refs), `question`, `scope:"saved-context-only"`, `retention:"private"` and the existing `authority_ref`. Parent IDs must be unique; each digest is non-null lowercase SHA256 and each revision equals `sha256:<digest>`. Parent order is part of the request meaning. The question is trimmed, well-formed Unicode with the same 1–2,000 UTF16-unit limit. Imported-answer, entity and arbitrary path parents are refused. Existing session, origin, owner scope and execution-configuration bindings still apply.

Every parent is read and validated by the exact owner reader before admission or inference. A missing or changed parent refuses the entire new request. Same-key retransmission compares the original meaning and returns the original identity and child ref without rerunning, including after parent loss; a changed question, selection or order conflicts. Busy admission remains `409 runner_busy`. After an uncertain reply, read `GET followups/<original-idempotency_key>` under the original owner scope rather than creating a replacement key.

Source statements are selected by local BM25 relevance to the question, adapted from the attributed dependency-free gpt-researcher lexical slice in `THIRD_PARTY_NOTICES.md`. Each parent gets up to `floor(40/n)` statement slots first; spare slots are redistributed by relevance. Ties and zero-overlap fallback preserve original order within each parent. Round-robin admission respects the 18,000 UTF8-byte material ceiling without shortening a statement or quote. Byte limits can reduce the final count below 40. Every parent's kept/total counts and original gaps are disclosed. Source observation and evidence IDs are qualified by parent to preserve identity when records overlap. Ranking locates text; it does not establish source support or semantic relevance.

All selected narratives remain unassessed prior synthesis. They are copied with parent labels separately from source evidence. If the complete selected narrative scope exceeds 110,000 UTF16 units, the operation refuses before admission rather than silently dropping a selected answer. Record-description context retains its existing bounded scope with omissions disclosed. One no-web discussion uses the unchanged authority prompt and citation validator. A stopped parent's state stays incomplete.

The ordinary private child `answer` has `followupOf.version:2`, `parents:[{ref,query,status}]`, and `selection:{method:"bm25-v1",question_sha256,per_parent:[{parent_id,total,kept}]}` in addition to its copied frozen scope, request/frozen digests and cited IDs. Reopening validates the closure and never loads or regenerates a parent. The child is searchable through the owner Library and readable as the existing exact `answer` source for Planning. This contract adds no Planning execution authority and makes no native research-quality or human-usefulness claim.

## Assessment confidence and generalization

These meanings stay separate:

| Meaning                  | What it describes                                                                               | What it does not establish                          |
| ------------------------ | ----------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Query relevance          | Fit to the interpreted need and inspected required constraints                                  | Intrinsic quality or personal usefulness            |
| Intrinsic Signal         | Source-bound evidence strength under a declared type rubric and policy                          | A probability that a claim or assessment is correct |
| Evidence sufficiency     | Whether enough support was inspected for a completed or provisional assessment under the policy | Measured assessment accuracy                        |
| Confidence in assessment | Reliability of the assessment itself                                                            | A value obtained by dividing Signal by 100          |

The current policies have no empirical probability calibration. Assessment confidence remains unknown. Source binding and deterministic invariants establish behavior under their test conditions; a matched passage does not establish entailment, independence or measured assessment accuracy. Decisive unsupported evidence must still cause abstention through the policy's null score and next-verification rules.

Type rubrics and cross-type fixtures test policy behavior, not semantic generalization. Broad quality claims require independent claim/outcome checks over diverse unseen needs, including failures and abstentions. Retention, rediscovery, source counts and provider token usage do not supply that evidence. Historical confidence/fit labels keep their original scope and do not become calibrated assessment confidence.

## Native assessment

Active native brief v7 uses `signal-strength-v10`. The model selects a suitable type rubric and binds each proposed dimension level to observations. Code validates those bindings, applies evidence ceilings and computes the score. Historical brief v5 selects v8 and v6 selects v9, with their original arithmetic.

| Dimension                   | Ordinary resources | Formal standards |
| --------------------------- | -----------------: | ---------------: |
| Claim and identity basis    |                 25 |               40 |
| Inspectable supporting work |                 25 |               20 |
| External scrutiny           |                 25 |               10 |
| Applicability and limits    |                 25 |               30 |

Each dimension has an ordinal level 0–4 or null. Contribution is weight × supported level ÷ 4; sum unrounded contributions and round once, halves upward. Unknown dimensions earn no credit and remain unknown. A score is an initial policy judgment, not calibrated probability or universal comparability across types.

Type rubrics cover software, scientific resources, news, discussion, learning, practices, standards and other resources. Software must use the software rubric; models/datasets use the scientific rubric; standards use the standard rubric. Reasons explain the selected rubric and suitable evidence.

Proposed levels are ceilings rather than automatic credit. Inspectable material supports at most level 1, worked examples 2, independent applied evidence 3 and independent replication 4. Maturity and attributable use have their own fixed ceilings. Identity/status authority distinguishes secondary accounts, primary authority, recognized authority and formal current status. Standards require inspected issuer authority and current official normative status.

Ordinary applicability may use explicitly bound verification/inspectable evidence at level 1: documented prerequisites, licence/access conditions and version scope. The model must establish applicability to the resource's own advertised scope. Query, model/provider and project suitability belong to relevance unless evidence concerns the resource itself. Inspectability cannot establish independent scrutiny or normative status.

External scrutiny in v10 requires a native-reviewed originating effort and relationship, with a short exact attribution passage and inspection reason bound to retained source evidence. Passages need at least eight characters after whitespace normalization and inspection reasons must remain nonempty after trimming; empty substring matches earn no credit. This remains a fallible native interpretation. Host is acquisition location; publisher may be a venue. Neither establishes who performed an investigation. Unbound, unmatched or unknown attribution earns no origin-dependent credit and leaves scrutiny unknown/provisional. If decisive work relies solely on unsupported replication/independent-application labels, abstain; do not manufacture a worked example. Separate explicit worked examples retain their own limited credit.

Equal known raw acquired-payload digests exclude extra support, including external-labeled copies of primary material. Null digests and equal short quotes do not establish payload equality. All locators and records remain retained; duplicate material is counted once without inferring creators. Grouping covers the effective active source set, including excerpt projections of the same selected physical payload. Missing group identity cannot earn independent credit. Native-reviewed effort identities and duplicate material jointly prevent copied or syndicated reports from minting additional support. Different raw digests do not prove distinct investigations. Shared venues or publishers do not suppress separately inspected efforts. Own-origin material, promotion and adverse findings cannot manufacture positive scrutiny. One independent support unit caps substantive scrutiny at half its weight. Software attention can earn at most five points from the strongest source-bound measurement:

`5 × min(1, log1p(count) / log1p(anchor))`

Anchors are 10,000 stars, 1,000 forks, 1,000,000 downloads, 1,000 discussion points and 10 attributable mentions. Counts must occur literally in the cited span; correlated counters are never added. Attention does not establish independent use.

Resolved identity, supported defining evidence, inspected decisive supporting work, contrary evidence and current status are required for a score. Decisive uncertainty or contradiction returns null with a reason and next verification. Explicit nondecisive gaps can produce a provisional score. Supported material/decisive failures cap work at level 1 and applicability at zero; adverse evidence earns no positive credit.

Future-dated or stale evidence earns no current credit. Evidence checks use 365 days, or 1,825 for publications/practices. Decisive stale evidence blocks assessment; retained material/decisive adverse evidence cannot silently disappear because its current status is unknown. The assessment records its explicit `asOf`, disposition, missing dimensions, reasons and next inspection.

## Query and advice

`query-relevance-v1` retains the interpreted need, required constraints, resource types and time window. Source-bound relevance uses these anchors:

| Value | Meaning                                             |
| ----: | --------------------------------------------------- |
|     0 | Conflicts with the need                             |
|    25 | Topic-only match                                    |
|    50 | Partial fit or material limits                      |
|    75 | Direct fit with a secondary limit                   |
|   100 | Direct fit with every inspected required constraint |
|  null | Unsupported                                         |

Constraint states are satisfied, conflicting or unknown. Relevance then stable identity determines relevance ordering. Correcting interpretation starts a distinct assessment and retains the prior run; it does not change intrinsic evidence.

Contextual priority v2 requires active supported defining and cited evidence. Ungrounded leads keep null priority. Proposed use/wrap/adapt actions are held at study with the original action preserved. They remain visible and manually saveable, but are excluded from advisory recommendations. Reasons, constraints, actions and alternatives remain inspectable.

Priority sorting orders by muted status, compatibility, contextual score, query relevance and stable identity; muted and incompatible/out-of-scope items sort later. Its relevance fallback is the ordinary query order: numeric relevance when present in the visible pool, otherwise match level. Explicit strength sorting retains its separate policy/rubric comparability rule. Sorting does not change retained assessments or admission decisions.

Discovery trails distinguish user seeds, configured parents, matched outlinks and model reports. A candidate-named verification query cannot prove unknown-name discovery. Source-family coverage is model-reported. A source scan differs from a result exposure; explicit per-entity feedback binds once to a verified introducing configured parent. Missing historical provenance earns no inferred credit.

## Saving and retrieval

Manual personal saving accepts unassessed leads without manufacturing evidence. Optional automatic personal saving starts disabled and requires completed v7/v8/v9/v10 assessment, supported resolved identity, direct relevance at least 75 and the configured Signal threshold, initially 75. Current automatic admission also requires positive observed support for basis, work and applicability. Zero in an essential dimension cannot be compensated by high points elsewhere. This is an admission safeguard, not a weight adjustment or recalculation of historical scores. Provisional assessments and unresolved decisive evidence hold automatic admission; manual retention and visibility remain available. Per-item admission/exclusion decisions remain private. Public inclusion keeps its separate validation/review boundary; saving is not publication.

Library identities qualify format and destination to distinguish native/historical and public/private copies. Literal matching is immediate. Permitted submitted meaning matching sends only the question, qualified keys, titles, bounded descriptions, kinds, capabilities and tags. Notes, projects, source text and credentials are excluded. Initial bounds are 200 records, 48,000 serialized characters and 120 seconds. Code validates IDs/scope/filters and hydrates original evidence; omitted population and failure/cancellation remain visible. No call occurs on keystroke. Public Pages has no runner.

## Evidence and exchange

Source URI, publisher, origin, publication date, fetch/check time and digests retain distinct meanings. A matched quote establishes occurrence, not entailment. Headless assessment reads bounded fetched text; short documents are complete and long documents use literal anchors plus distributed windows within 48,000 characters. Unknown access/licence does not establish free or open-source status. Disclosed scope limits are not automatically contrary evidence.

Evidence is immutable. Excerpt digests distinguish projections over the same raw document; current evidence/checks explicitly select active snapshots without rewriting first-fetch or publication dates. New `identityVersion2` observations bind claim wording, quote and judgment. Corrections append successor judgments; changing excerpts cannot revive a retired judgment. Unmarked historical text/identity decoders retain their original semantics. Saving retained history cannot downgrade a newer receipt.

Policy v10 retains unsuperseded material/decisive adverse findings even when their source is inaccessible, inactive, stale or uncertain. Those conditions produce an unknown assessment with a specific next check; retrieval failure is not disproof. Verified contradictions bound to identity, work or applicability also hold the assessment. A verified, current, source-bound refutation or successor may resolve the same claim and scope. Changing a statement or indicator cannot erase the earlier adverse finding; unavailable or unverified successors cannot resolve it. Direct v10 refreshes retain earlier decisive bindings, so omitting a prior contradiction or uncertainty cannot restore completed status. Current admission history is also carried independently of numerical policy, including old-format imports without a typed basis. An older numerical receipt may remain 100/completed while current admission is held; the guard does not recalculate that receipt. Verified applicable failures retain the existing work/applicability caps. Current automatic admission applies these holds independently of historical numerical receipts. The writer retains decisive observation IDs on the entity projection, preserves compatible older basis metadata and never mutates the incoming result while merging. Derivation views show current holds separately when the historical numerical assessment lacks those reasons, and attribution panels display the same binding status used by scoring.

Frozen schema-v1 interchange preserves original evidence and legacy confidence/fit labels. Native strengths, fetch dates, query assessment and contextual priority use separate extensions. Query exchange binds exported source IDs against the bundle. Context recommendations retain candidate/claim IDs and exclude ungrounded advice. Private notes/feedback are never exported; advisory requests grant no activation authority.

Configured-live research is `model-led`; invoking-host research is `agent-assisted`. Fixtures remain fixture-labelled and cannot enter real evidence admission. Re-export changes export time/code revision, not original observations or discovery time. Requested frozen review may correct interpretation without hiding acquisition failures or original private receipts.

## Direct primary-source checks

A caller can explicitly request one proposition check against one or two selected fresh primary URLs without supplying a research-answer parent. The request-origin receipt preserves the question, context, proposition and source order. Existing linked checks still require the immutable original answer and selected citation membership. Both origins use the same safe acquisition, material bounds and one frozen native judgment. Acquisition failure is not contradiction, matched text is not entailment, and Unknown confidence does not become a probability. A direct verdict creates no scored entity and grants no installation or execution authority. Its private negative and incomplete outcomes remain recoverable through ordinary temporary-run cleanup. Memory mode writes no history or source cache.

## Private document selection

Signals accepts an explicit bounded local import of PDF, Markdown, HTML or plain UTF8 text. The closed import input is `{name,media_type,bytes_base64}`; names are display basenames and HTTP never accepts paths. PDF import uses the optional exact pypdf 6.15.0 dependency through a fixed stdin-only helper. Import performs no model call, network acquisition, OCR, project mutation or public admission. HTML is parsed as inert text with no scripts or resources fetched.

Private `.signals/private-documents.json` records retain the original bytes, `raw_sha256`, `record_sha256`, extractor identity, qualification and ordered pages `{number,text,text_sha256}`. Reopen validates the closed record and digest closure; it does not reparse or silently repair stored text. `RecordRef` uses owner `signals-ai`, kind `private_document`, UUID id, and the same SHA256 digest/revision binding as source captures. Lists return exact refs and metadata only, without original bytes or page text. Reopen returns `{ref,document}` with page text, never raw bytes or disk paths.

Import accepts at most 4 MiB per file and 50 PDF pages. Complete extraction is refused above 48,000 UTF16 units or 96,000 UTF8 bytes; the store is limited to 20 documents and 12 MiB aggregate original bytes. PDF extraction is text-layer only, refuses encrypted/malformed/image-only files and reports pypdf's potential reading-order/table limits. Markdown and plain text preserve well-formed UTF8 text; HTML uses the existing inert Readability/layout projection. None of these limits or digests proves source completeness, authenticity or truth.

`selectPrivateDocument(root,{document_ref,pages},origin)` requires an exact `private_document` ref, unique 1–8 in-range pages and a validated loopback HTTP origin. It returns `{sources,document_ref,pages,qualification}` with one full page per Research `FrozenSource`; the source URI names the local page route and is not a public verification claim. Only the selected text enters the existing frozen Research boundary. Source text and caller notes remain untrusted data. Import, listing, reopen and selection themselves invoke no AI or external transport.

## Private PDF reader

The optional `.signals/private-reader.json` retains up to 50 reader IDs with a current one-based PDF page and up to 50 immutable exact annotations each. `POST private-reader/bytes` accepts only `{document_ref,raw_sha256}` and returns base64 original PDF bytes only after reloading the complete integrity-checked owner record and matching both identities; it is session-, origin- and epoch-guarded and returns `no-store`. Existing document list/open/page routes continue to omit raw bytes. Reader create/reopen uses an explicit UUID and exact PDF ref/hash; revision and selected-passage export use expected reader revision plus digest. Annotation `{id,page,start,end,quote,page_sha256,note}` binds the exact extracted page string using UTF16 offsets that cannot split a surrogate pair. Quotes made only of Unicode whitespace are refused before saving and when retained annotations are reopened or selected; every other quote is preserved exactly without normalization. Reopen, revise and select revalidate the page digest and exact quote. The current page persists; create retries retain their initial page meaning. Selection returns only up to eight explicitly selected quoted passages plus a manifest with raw/page hashes, range, exact ref and qualifications, never the PDF or unselected annotation bodies. This is user interpretation for a frozen research handoff, not truth or acceptance. PDF.js page numbers align with pypdf's one-based page order; pypdf offsets do not map to PDF glyph coordinates.

Declared policies replay unchanged. Native brief v4 selects v7; native v1–v3 and full proposals keep their original readers. The reducers in `packages/domain/src/search-score.ts` and `search-assessment.ts` define exact arithmetic and normalizers.

| Policy               | Preserved meaning                                                                                                                                           |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `signal-strength-v0` | All unsuperseded snapshots; ordinary six-feature weights for every kind                                                                                     |
| v1                   | Explicit snapshot selection; separate standard weights and first-fetch formal-status aging                                                                  |
| v2                   | Raw-document-stable judgment bases, selected-digest excerpts and actual reacquisition checks                                                                |
| v3                   | Independent third-party credit across source families; literal text and normalization-bound grouping                                                        |
| v4                   | Source-bound numeric attention using the capped anchors above                                                                                               |
| v5                   | Future publication dates earn no dated-currentness credit; unsupported qualitative freshness is capped at half                                              |
| v6                   | Explicit current-status evidence with same-source primary-or-higher issuer authority can earn currentness within the smaller of the type window or 365 days |
| v7                   | Four bound type-rubric dimensions, decisive uncertainty and evidence ceilings; inspected verification does not supply ordinary applicability credit         |
| v8                   | The native assessment contract above, including limited inspected ordinary applicability                                                                    |
| v9                   | Initial retained adverse/contradiction holds; frozen candidate semantics at its declared code pin                                                           |
| v10                  | v9 arithmetic plus scope-preserving negative history, retained decisive bindings, inspected origin-dependent credit and duplicate-payload exclusions        |

For v0–v6, ordinary weights are corroboration 25, adoption 20, maturity 20, currentness 15, authority 10 and verification 10. Standards from v1 use 10/0/15/25/40/10. The strongest supported risk subtracts 5, 15 or 25. Unknowns earn zero without renormalization. Own-origin/mirror groups cannot create extra independent credit. Currentness windows are 90 days for software/services/other, 30 for models, 365 for datasets/learning resources/products/organizations, 730 for practices and 1,825 for publications/standards. Mutable standard-status checks expire after 365 days, capping currentness at half and formal-current authority at three-quarters until reviewed. Earlier policies retain their declared snapshot/date rules.

Historical `signal-review-v1` findings require a separately attributed model review: relevance, evidence applicability, actionable usefulness and clarity/scope each at least 3/4, with no fatal blockers or unresolved material claims. Its weakest rating × 25 is the review score. Withdrawal removes a finding from default results while preserving exact evidence/downloads. Corrected frozen findings require successor identities and review.
