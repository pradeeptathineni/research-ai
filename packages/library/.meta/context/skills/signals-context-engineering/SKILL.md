name: signals-context-engineering
description: Inspect Signals across package boundaries or recover noisy command output with a bounded source map; skip narrow settled edits.
---

State the question and evidence needed. Start with `rg --files`, targeted searches and
narrow reads. For ownership questions spanning packages, run `npm run context:pack`
and inspect `.meta/context/local/signals.xml`. It is a disposable secret-scanned map
with a 30,000-token ceiling; reopen exact source before editing or asserting behavior.
It excludes private state, fixture data and historical reports.

When output is compressed, recover omitted detail from its `raw_ref` before rerunning
work. CCA recovery can be normalized/redacted and does not promise original bytes.
The optional host hook requires trust/activation; configuration does not establish
use. Keep generated output and receipts ignored and local.

Use focused references rather than loading every guide. New context tooling needs an
observed navigation, fidelity or cost gap that searches, the map and raw recovery
cannot solve. Compare critical-fact retention, reversibility, privacy, maintenance
and real task outcomes; upstream savings are claims, not local results.
